# bevy_bhtn AGENTS.md

## Purpose
Headless **Hierarchical Task Network** planner for Bevy AI (built for CDDA-style games), built on **function-graph reflection**: tasks are plain Rust functions whose zero-sized fn-item types are the graph identity — no marker structs, no string ids, no reflection. At startup the root function is **recorded** and **baked** into a flat indexed graph; the runtime planner searches the arrays directly (O(1) node lookups, allocation-light backtracking). State is **ordinary Bevy components**: preconditions/effects are monomorphized closures over component references, simulated on a dense [`PlanState`] scratchpad. The planner runs both **forward** (MTR backtracking with look-ahead pruning) and **backward / goal-state** planning.

## Ownership
- Lives at the repo root (package `bevy_bhtn`). The **planner core** (`planner`, `back_planner`, `summaries`, `lookahead`, `domain`, `tasks`, `state`, `error`) is ECS-driver-free: planners take a `&PlanState` scratchpad and never require a live `World` mid-search. Its only dependency is `bevy_ecs` (for the `Component` trait bound and the `World`/`Entity` extraction seam) — there is **no `bevy_reflect`** anywhere.
- The **ECS driver** (`src/ecs.rs`) is the execution seam: the `HtnAgent` component, the `HtnConfig` resource, and the exclusive `htn_ai_system`. Dev-dependencies (tests/benchmarks) also use `bevy_ecs` (with `multi_threaded`) to exercise the planner the way a game would.
- Domain data (`HtnDomain`, `Task`, `CompoundTask`, `PrimitiveTask`, `Method`, `Precondition`, `Effect`, `Action`) is plain baked data; `Precondition`/`Effect` carry type-erased closure pointers plus their component read/write slot sets.

## Local Contracts
- **API layout**: task functions → `HtnDomain::from_root(root_fn)` → optional `.goal(goal_fn)` → `.build()` → `HtnPlanner` (forward) / `BackPlanner` (backward) → `ecs` execution. Compound tasks may declare a [`SelectionPolicy`] (`.select(...)`: FirstMatch default, HighestUtility, WeightedRandom, Custom ranker) and branches may carry `.named(...)` + `.utility(...)/.utility_fn(...)`; branches may also declare partially-ordered member sets (`.subtask(f) -> SubtaskHandle`, `.before(a, b)`, `.any_order((f1, f2, ...))` — tuple-based, see the AnyOrder identity note below); primitives may declare `.cost(...)/.cost_fn(...)` (inert under DepthFirst; the step costs of CostBounded — `.cost(c)` also feeds the bake-time `min_cost` lower bound, `.cost_fn` clears it, last call wins, negatives clamp to 0).
- **Task functions** (`fn name(task: &mut TaskBuilder)`): calling `.branch()` makes the task compound (ordered methods, each `.branch().precondition(...).then(sub_fn)...`; a branch with no `.then` is a terminal empty refinement); calling `.precondition/.effect/.expected/.action` makes it primitive; mixing the two is a `HtnError::Builder`. `.then(f)` captures `TypeId::of::<F>()` + `type_name::<F>()` (last path segment = task name) and queues `f` for expansion — each function is recorded exactly once; recursive/repeated references become plain graph edges. Empty terminal branches are the idiom for "done" methods.
- **Subtask ordering** (`src/order.rs` + bake in `domain.rs`): a method's members are a **total order** (`then` chain, default) or a **partially-ordered set** (`SubtaskOrder::Partial{preds, orders, first}`). Semantics: `then` = after every prior member; `subtask` = after every prior `then` member, unordered vs. other unordered members; `before(a, b)` = explicit edge. **`any_order` takes a tuple of task fns, never an array** — an array coerces distinct fn items to one `fn(&mut TaskBuilder)` pointer type and collapses their identities (pinned by the AnyOrder docs). Bake validates acyclicity (cycle → `HtnError::Builder`) and the 64-member mask limit, caps the topological-order count at `LINEARIZATION_CAP` (64), and normalizes to `Total` only when the single order *is* the declaration order (a single non-declaration order stays partial — `Total` would push the wrong sequence). Search-time scheduling: commitment pushes topological order #0 (the baked `first`); on downstream failure `backtrack` re-queues a `Linearize` entry that re-commits the SAME method with the next order (state/plan/mtr/queue restored to commitment time; retries run unpinned; the MTR keeps only the method index) before other methods are offered. The compiled `Plan`, executor, and driver are unchanged. **Envelope**: lexicographic enumeration + the 64-order cap make cross-member dependencies in unconstrained sets reliably schedulable only up to ~4 members (pinned by `wide_set_envelope_buried_dependencies`) — wide/data-driven member sets belong in recursion over components (see `benches/wide_sets.rs`; a clean 8-member set is *cheaper* than the equivalent chain because its sweep runs in set semantics, and one linearization retry costs ~130 ns).
- **Baking** (`HtnDomain::build`): validates (mixed declarations, branchless compound/root, duplicate names), assigns contiguous task indices (root = 0, FIFO discovery order), computes the name/`TypeId` index maps, and infers the summaries.
- **Component closures**: `.precondition(|a: &Ammo, b: &Vision| bool)` and `.effect(|a: &mut Ammo, b: &Cover| ...)` take up to 8 annotated params; **`&mut T` marks a component the effect writes, `&T` a read-only one** — any `&`/`&mut` mix at any arity up to 8 (the `PlanParam` trait in `src/tasks.rs`: one linear tuple impl per arity, each parameter unifying against the `&T`/`&mut T` impl; `const IS_WRITE` is const-folded into the write list, so reads are never journaled for rollback nor committed to the real entity — only what the closure actually mutates costs anything). Multi-arg effects use `PlanState::disjoint_slots` for alias-free scratchpad access; no parameter may name the same component type twice (a `&mut`/`&` pair on one slot would alias). `.expected(...)` effects are planning-only (possible, never guaranteed writes); `.action(|cmds: &mut EntityCommands| ...)` is the real-world dispatch (Arc'd, flushed by the driver).
- **State** (`src/state.rs`): `PlanComponent` = `Component + Clone + Default + Send + Sync`. `PlanState` is a **contiguous byte pool** — one allocation (`Pool`, aligned to the registry's maximum slot alignment), each registered component owning an alignment-correct slot region fixed at registration (the registry is a **typestate pair**: `RegistryBuilder` owns the layout inline during domain recording and is the only type with `index::<T>()` — with a `HashMap<TypeId, usize>` lookup — and `freeze()` produces the frozen `ComponentRegistry` (`Arc` layout, read-only) that `HtnDomain.components` holds; late registration after a `PlanState` exists is a compile error, not a runtime panic). The layout is an **AoS slot table** — one `Vec<Slot>` per registry, each `Slot` carrying its `TypeId`/name/offset/size/align plus its monomorphized `fetch`/`write`/`clone`/`drop`/`default` fns — so every per-slot loop (extract/refresh/clone/`copy_from`/drop) walks a single contiguous array. All slots are always initialized. This makes the search's per-node operations allocation-free: `clone` is one pool alloc + per-slot monomorphized clones, `copy_from` reuses an existing pool (the look-ahead sweep's scratch), rollback snapshots/restores are **deep clones through an aligned journal arena** (the journal OWNS its copies — a bitwise snapshot dangles the moment an in-place mutation frees a heap allocation, and reanimating it on restore is a double free; restore = drop-current + clone-back + drop-journal-copy, so every allocation has exactly one owner at every point; plain-data slots clone as a `memcpy`; copies the search never restores (successful-plan / sanity-limit exits) are dropped by `Rollback`'s `Drop` through the baked droppers), and `get`/`get_mut` are aligned pointer casts (no `dyn Any` downcasts, no per-component boxes). `PlanState::extract(&world, entity, &registry)` fetches every slot (missing → `Default` via monomorphized `FetchFn`); `PlanState::build(&registry).set(v).finish()` constructs one without a World (unset slots materialize via a monomorphized `DefaultFn` — no scratch `World`; a builder dropped before `finish` releases its `set` values); `refresh(&world, entity)` and `write_back_with(&world, entity, indices)` need no registry argument — the scratchpad owns its layout `Arc`, so a wrong-registry misuse is unrepresentable. **Soundness**: effect closures taking `&mut` to the same component type twice are rejected at build time (`assert_distinct_slots` — the slots would alias); `disjoint_slots` re-checks in debug builds as defense in depth.
- **Selection policies** (`src/selection.rs`): ranking happens once per choice-point visit (precondition validity is constant there); the ranked order is *not* stored in the frame — every policy re-derives it deterministically on revisit (the WeightedRandom sampler's nonce is the restored `plan.len()`), so backtracking resumes down the same ranked list. FirstMatch keeps a fast path (direct `find_method` scan, no ranking). Custom rankers write into a caller scratch Vec; their output is sanitized (omitted valid branches are appended in declaration order — a bad ranker cannot make branches unreachable).
- **Search strategies** (`src/selection.rs`): `HtnSearchStrategy` on `HtnConfig` (DepthFirst default, DepthFirstFailFast, CostBounded, Custom(Searcher)); per-agent `SearchOverride` component overrides strategy/sanity budget. **CostBounded** is branch-and-bound DFS over accumulated primitive cost: the planner tracks `g` (restored per-frame on backtrack like `plan`/`mtr` lengths), records the cheapest *complete* plan at queue-drain and keeps searching (anytime), and prunes commitments/primitive steps whose `g + min_cost(remaining)` cannot strictly beat the best (unannotated primitives cost 0 → degenerates to DepthFirst). `plan_traced` emits `DecompositionTrace` per commitment (Selected/PrecondFailed/Backtracked); the driver bridges to `Messages<DecompositionTrace>` when `HtnConfig.debug_trace` is set. The planner core never touches Bevy event types.
- **ECS execution** (`src/ecs.rs`): `HtnAgent` (component: `Option<Plan>` + cursor — the agent's state IS its components), `HtnConfig` (resource: domain + strategy + lookahead/sanity/debug_trace tuning), and `htn_ai_system` (exclusive system, one tick per agent: plan if planless → **re-validate the next step's preconditions against the real world** (drift ⇒ drop plan, replan next tick) → dispatch the action's `EntityCommands` + `world.flush()` (re-extracting the scratchpad afterwards so effects see post-action state) → commit effects to the real components → advance cursor / drop finished plan). Step resolution is a **flat array walk**: `plan.step_task(cursor)` → `domain.tasks[idx]` — no name lookups on the hot path. An empty plan is stored as planless (never wedges the agent). **Hot-reload** (`hotpatching` feature → `bevy_ecs/hotpatching`, Dioxus Subsecond): `HtnConfig::with_rebuild(domain, rebuild)` stores a domain rebuild closure; the driver change-detects `bevy_ecs::HotPatchChanges` and, on a patch, re-records + re-bakes the domain through it (the baked domain is *data* — compiled closures — so patching task-fn bodies requires a rebuild), swaps it in, drops the parked scratchpad (fresh registry), and clears every agent's plan. A failing rebuild keeps the old domain; the patch tick is recorded either way (no retry loop). Run the game under `dx serve --hotpatch`; only the *tip* crate's task functions are observed.
- **Planner signatures**: `HtnPlanner::plan(&mut self, root_name, &PlanState) -> Plan` (best partial plan on failure, never errors; `Plan.status` — `PlanStatus::Complete` vs `Partial` — reports whether the decomposition finished or the sanity budget / fail-fast cut it short; `set_lookahead`, `set_sanity_limit`); `BackPlanner::plan(&mut self, goal_name, &PlanState) -> HtnResult<Plan>` (greedy reverse chaining, `HtnError::NoPlan` on plateau, empty MTR, always `Complete`).
- **Inferred summaries** (`src/summaries.rs`): at bake time every task gets a [`TaskSummary`] — `required_fields` (greatest fixpoint guarded by `term` + `E_f` least fixpoints), `possible_writes`/`guaranteed_writes` (least fixpoints; `.expected` counts as possible, never guaranteed) — plus per-method `possible_writes`. Adapted from Olz/Biundo/Bercher (AAAI 2021 / JAIR 2025); the universe is the **component slot indices** (`ComponentRegistry`), sets are [`FieldSet`] word-bitsets.
- **Look-ahead pruning** (`src/lookahead.rs`, Olz & Bercher SoCS 2023): before committing each method, the sweep runs that **method's own subtask sequence** against an optimistic state (lazily-cloned `PlanState` + an "unknown components" overlay fed by method `possible_writes`; the sequence's last task's effects are never applied). Preconditions on unknown components are "maybe" and never prune. Because effect closures are opaque, every written component conservatively becomes unknown. Verdicts: `DeadEnd` → skip the method; `Refine(pins)` → inevitable refinements pinned per subtask **occurrence** (pins travel on the queue entry). **Budget refutation**: the sweep accumulates `min_yield` and refutes methods that cannot finish within the remaining step budget (subsumes non-terminating tasks, `min_yield == usize::MAX`). Pins never change *which* plan is found — only the effort. **Set semantics** (`set_semantics` flag): for partially-ordered methods the sweep pre-unions every member's `possible_writes` into the overlay and never applies effects sequentially — pruning weakens but stays sound (a dead-end verdict means every member fails in every linearization); pins are keyed by member position, which the first topological order shares.
- **Structure analysis** (in [`TaskSummary`], Toad/Alford-style): `terminating`, `min_yield`, `min_cost`, `recursive`, `self_embedding`, `tail_recursive` — position-tagged reachability over the decomposition graph at bake time. `min_cost` is the min-cost fixpoint twin of `min_yield` (f32, `INFINITY` for non-terminating; primitives contribute their static `.cost`, dynamic `cost_fn` counts 0) and each baked `Method` carries its subtask-sequence `min_cost` sum for CostBounded pruning. Partially-ordered methods use order-independent conservative extensions: `min_yield`/`min_cost`/write sets are sums/unions over members (each runs exactly once); `required_fields` requires a component to be read by a member **no member can write**; structure flags treat every set member as both non-first and non-last.
- **Performance**: task names are interned [`Ustr`]s; the hot loop works on `usize` task indices; [`Plan`] is a **compiled step program** — `steps: Vec<u32>` (domain task indices, execution = flat array walk) plus parallel interned `names` for display. Backtracking is allocation-free: append-only `plan`/`mtr` restored by truncation (frames snapshot `mtr_len` *before* their own method push so a retry replaces the failed entry — a stale MTR entry here is a correctness bug, pinned by `mtr_after_backtrack_records_only_the_chosen_method`), queue suffixes snapshotted per frame as `SmallVec<[_; 4]>` (inline for the common 2–5-subtask case; a persistent/structurally-shared queue making this O(1) is a known future optimization — a bare length is unsound because a completed subtree's frame can be backtracked into after the search consumed part of the suffix, pinned by `backtracking_restores_ancestor_suffix_after_tail_failure`), and the rollback journal (`Rollback`: aligned arena of deep-cloned slot values + `(slot, offset)` ops) restores only the slots each effect wrote — drop-current, clone-back, drop-journal-copy (soundness pinned by `rollback_of_a_replaced_heap_value_frees_everything_exactly_once` / `rollback_of_repeated_unmutated_snapshots_frees_everything_exactly_once`, which use a self-verifying heap cell because drop-counters stay balanced across double-frees). The look-ahead sweep reuses its private `PlanState` clone across sweeps (`copy_from`, no re-allocation), leaves its pin verdicts in the caller's scratch (no `mem::take`), and evaluates each compound method's preconditions once (single pass: survivors collected, then pin + optimistic propagation). The driver reuses one `DriverScratch` resource (agent-entity `Vec` + one `PlanState`, `refresh`ed in place per plan/validate/re-extract phase — zero steady-state allocations; each baked `PrimitiveTask` carries its commit/guaranteed write-slot lists so no per-step collection happens) and plans by root **index** (`plan_index`), not name.
- Error handling goes through `HtnError`/`HtnResult` (`Builder`, `UnknownTask`, `NoPlan`, `SanityLimit`).
- Public API + `prelude` are the seam; keep internals private unless a planner genuinely needs them.

## Work Guidance
- All string-typed identifiers are [`Ustr`]; task/goal names come from `type_name` — never reintroduce user-supplied name strings.
- New planner algorithm → new module under `src/`, expose through `prelude`, and add tests via the shared `tests/common/mod.rs` `HtnTestBed`. **Domain fixtures live in `benches/common/mod.rs`** (`miner_domain()`, `outpost_domain()`, `gate_domain()`, `doomed_recursion_domain()` — function-defined, the single source of truth shared by tests *and* benches; `tests/common/mod.rs` re-exports them via `#[path]` include). Terminal "done" methods are empty branches (`.branch().precondition(...)` with no `.then`), matching the original fixtures' plan shapes.
- Components participating in planning derive `Component + Clone + Default (+ Debug)`; closure params must be annotated so slot indices can be captured.
- When wiring into `cdda_sim::ai` later: `cdda_sim` may depend on `bevy_bhtn`, never the reverse.
- **Tests** use the `HtnTestBed` pattern (`tests/common/mod.rs` wraps a built `HtnDomain`, exposes `plan_forward` / `plan_forward_lookahead` / `plan_backward` over `PlanState`s).
- **Benchmarks** live in `benches/ai_throughput.rs` (Criterion, flat miner domain), `benches/deep_ai.rs` (Criterion, deep outpost + Bevy Relationships), `benches/lookahead.rs` (Criterion, look-ahead on/off A/B), and `benches/competitor_comparison.rs` (like-for-like vs `bevy_bae` and a vendored `bevy_htnp` on the shared fetch-item domain). All consume `benches/common/mod.rs` (except the comparison, which is self-contained) and run one **plan → execute-the-full-plan** episode per measured iteration (`execute_plan`; scratchpads reset per iteration — one complete AI decision plus its execution, no replan loop). The first two run the planner **through a real Bevy `Schedule`** via `Query::par_iter_mut` over the multi-threaded executor (scratchpads stored as components; note bevy_ecs 0.18 tuples do NOT imply system ordering — use `.chain()`); their single-actor overhead cases mirror `run_ai`'s exact work shape with `Throughput::Elements(1)` pinned so Criterion's group-wide thrpt column stays sane; `benches/lookahead.rs` calls the planner directly (isolating the algorithmic win from ECS overhead). The comparison bench measures one full episode per actor (end-to-end) plus a **steady-state frame** — one frame of a continuing episode: agents execute/validate their next step, planless agents replan, finished agents reset (amortized) — at 1k/10k/50k agents (deep: 100/1k), single-threaded, each library through its native per-frame cadence; see its module docs for the workload-contract caveats (BAE's per-agent entity trees, htnp's time-sliced planner) and the deep domain's `DEEP_SANITY_LIMIT` requirement.

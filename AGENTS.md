# bevy_bhtn AGENTS.md

## Purpose
Headless **Hierarchical Task Network** planner for Bevy AI (built for CDDA-style games), built on **function-graph reflection**: tasks are plain Rust functions whose zero-sized fn-item types are the graph identity — no marker structs, no string ids, no reflection. At startup the root function is **recorded** and **baked** into a flat indexed graph; the runtime planner searches the arrays directly (O(1) node lookups, allocation-light backtracking). State is **ordinary Bevy components**: preconditions/effects are monomorphized closures over component references, simulated on a dense [`PlanState`] scratchpad. The planner runs both **forward** (MTR backtracking with look-ahead pruning) and **backward / goal-state** planning.

## Ownership
- Lives at the repo root (package `bevy_bhtn`). The **planner core** (`planner`, `back_planner`, `summaries`, `lookahead`, `domain`, `tasks`, `state`, `error`) is ECS-driver-free: planners take a `&PlanState` scratchpad and never require a live `World` mid-search. Its only dependency is `bevy_ecs` (for the `Component` trait bound and the `World`/`Entity` extraction seam) — there is **no `bevy_reflect`** anywhere.
- The **ECS driver** (`src/ecs.rs`) is the execution seam: the `HtnAgent` component, the `HtnConfig` resource, and the exclusive `htn_ai_system`. Dev-dependencies (tests/benchmarks) also use `bevy_ecs` (with `multi_threaded`) to exercise the planner the way a game would.
- Domain data (`HtnDomain`, `Task`, `CompoundTask`, `PrimitiveTask`, `Method`, `Precondition`, `Effect`, `Action`) is plain baked data; `Precondition`/`Effect` carry type-erased closure pointers plus their component read/write slot sets.

## Local Contracts
- **API layout**: task functions → `HtnDomain::from_root(root_fn)` → optional `.goal(goal_fn)` / `.root(f)` (extra compound roots, e.g. an AHTN opponent) / `.share_task(f)` / `.insertable(f)` / `.with_insertion()` → `.build()` → `HtnPlanner` (forward) / `BackPlanner` (backward) / `Ahtn` (adversarial) → `ecs` execution. Compound tasks may declare a [`SelectionPolicy`] (`.select(...)`: FirstMatch default, HighestUtility, WeightedRandom, Custom ranker — baked data, lives in `domain` with the network) and branches may carry `.named(...)` + `.utility(...)/.utility_fn(...)`; branches may also declare partially-ordered member sets (`.subtask(f) -> SubtaskHandle`, `.before(a, b)`, `.any_order((f1, f2, ...))` — tuple-based, see the AnyOrder identity note below); primitives may declare `.cost(...)/.cost_fn(...)` (inert under DepthFirst; the step costs of CostBounded — `.cost(c)` also feeds the bake-time `min_cost` lower bound, `.cost_fn` clears it, last call wins, negatives clamp to 0). The GTN module (`src/gtn.rs`) compiles task sharing (Theorem 4.8's `fin_o` scheme — marker via expected effects, planning-only) and task insertion (stop-first gap compound, repair-only) into the recorded network at bake time; see its module docs for the contracts.
- **Task functions** (`fn name(task: &mut TaskBuilder)`): calling `.branch()` makes the task compound (ordered methods, each `.branch().precondition(...).then(sub_fn)...`; a branch with no `.then` is a terminal empty refinement); calling `.precondition/.effect/.expected/.action` makes it primitive; mixing the two is a `HtnError::Builder`. `.then(f)` captures `TypeId::of::<F>()` + a display name (named fns: `type_name` last segment; closures: the reference site's `file:line:col` via `#[track_caller]` — `{{closure}}` is never stored) and queues `f` for expansion — each function is recorded exactly once (under the FIRST reference's name); recursive/repeated references become plain graph edges. Empty terminal branches are the idiom for "done" methods.
- **Subtask ordering** (`src/order.rs` + bake in `domain.rs`): a method's members are a **total order** (`then` chain, default) or a **partially-ordered set** (`SubtaskOrder::Partial{preds, orders, first}`). Semantics: `then` = after every prior member; `subtask` = after every prior `then` member, unordered vs. other unordered members; `before(a, b)` = explicit edge. **`any_order` takes a tuple of task fns, never an array** — an array coerces distinct fn items to one `fn(&mut TaskBuilder)` pointer type and collapses their identities (pinned by the AnyOrder docs). Bake validates acyclicity (cycle → `HtnError::Builder`) and the 64-member mask limit, caps the topological-order count at `LINEARIZATION_CAP` (64), and normalizes to `Total` only when the single order *is* the declaration order (a single non-declaration order stays partial — `Total` would push the wrong sequence). Search-time scheduling: commitment pushes topological order #0 (the baked `first`); on downstream failure `backtrack` re-queues a `Linearize` entry that re-commits the SAME method with the next order (state/plan/mtr/queue restored to commitment time; retries run unpinned; the MTR keeps only the method index) before other methods are offered. The compiled `Plan`, executor, and driver are unchanged. **Envelope**: lexicographic enumeration + the 64-order cap make cross-member dependencies in unconstrained sets reliably schedulable only up to ~4 members (pinned by `wide_set_envelope_buried_dependencies`) — wide/data-driven member sets belong in recursion over components (see `benches/wide_sets.rs`; a clean 8-member set is *cheaper* than the equivalent chain because its sweep runs in set semantics, and one linearization retry costs ~130 ns).
- **Baking** (`HtnDomain::build`): validates (mixed declarations, branchless compound/root, duplicate goal functions), assigns contiguous task indices (root = 0, FIFO discovery order), computes the name/`TypeId` index maps, and infers the summaries. Display names are NOT identity — same-named task fns (different modules) and closures (`{{closure}}`) bake as distinct tasks; the name map is first-wins introspection only. Expansion (queued `.then` functions → placeholder + record) runs through ONE shared `expand_queue` helper used by `from_root`, `root`, and `insertable`; `TaskBuilder::finish` writes into the explicit placeholder index it was constructed with (structural, not "last task" convention).
- **Component closures**: `.precondition(|a: &Ammo, b: &Vision| bool)` and `.effect(|a: &mut Ammo, b: &Cover| ...)` take up to 8 annotated params; **`&mut T` marks a component the effect writes, `&T` a read-only one** — any `&`/`&mut` mix at any arity up to 8 (the `PlanParam` trait in `src/tasks.rs`: one linear tuple impl per arity, each parameter unifying against the `&T`/`&mut T` impl; `const IS_WRITE` is const-folded into the write list, so reads are never journaled for rollback nor committed to the real entity — only what the closure actually mutates costs anything). Multi-arg effects use `PlanState::disjoint_slots` for alias-free scratchpad access; no parameter may name the same component type twice (a `&mut`/`&` pair on one slot would alias). `.expected(...)` effects are planning-only (possible, never guaranteed writes); `.action(|cmds: &mut EntityCommands| ...)` is the real-world dispatch (Arc'd, flushed by the driver).
- **State** (`src/state.rs`): `PlanComponent` = `Component + Clone + Default + Send + Sync`. `PlanState` is a **contiguous byte pool** — one allocation (`Pool`, aligned to the registry's maximum slot alignment), each registered component owning an alignment-correct slot region fixed at registration (the registry is a **typestate pair**: `RegistryBuilder` owns the layout inline during domain recording and is the only type with `index::<T>()` — with a `HashMap<TypeId, usize>` lookup — and `freeze()` produces the frozen `ComponentRegistry` (`Arc` layout, read-only, carrying the builder's `HashMap<TypeId, usize>` slot map so `ComponentRegistry::get`/`PlanStateBuilder::set` resolve in O(1)) that `HtnDomain.components` holds; late registration after a `PlanState` exists is a compile error, not a runtime panic). The layout is an **AoS slot table** — one `Vec<Slot>` per registry, each `Slot` carrying its `TypeId`/name/offset/size/align plus its monomorphized `fetch`/`write`/`clone`/`drop`/`default` fns — so every per-slot loop (extract/refresh/clone/`copy_from`/drop) walks a single contiguous array. `FieldSet` (the component-slot bitset) also lives here: the universe it indexes is the registry, and every bake-time analysis (summaries, look-ahead, back-planner coverage) consumes it. All slots are always initialized. This makes the search's per-node operations allocation-free: `clone` is one pool alloc + per-slot monomorphized clones, `copy_from` reuses an existing pool (the look-ahead sweep's scratch), rollback snapshots/restores are **deep clones through an aligned journal arena** (the journal OWNS its copies — a bitwise snapshot dangles the moment an in-place mutation frees a heap allocation, and reanimating it on restore is a double free; restore = drop-current + clone-back + drop-journal-copy, so every allocation has exactly one owner at every point; plain-data slots clone as a `memcpy`; copies the search never restores (successful-plan / sanity-limit exits) are dropped by `Rollback`'s `Drop` through the baked droppers), and `get`/`get_mut` are aligned pointer casts (no `dyn Any` downcasts, no per-component boxes), with `get_by_type`/`get_mut_by_type` as the type-addressed convenience counterparts (slot resolved through the frozen map). `PlanState::extract(&world, entity, &registry)` fetches every slot (missing → `Default` via monomorphized `FetchFn`); `PlanState::build(&registry).set(v).finish()` constructs one without a World (unset slots materialize via a monomorphized `DefaultFn` — no scratch `World`; a builder dropped before `finish` releases its `set` values); `refresh(&world, entity)` and `write_back_with(&world, entity, indices)` need no registry argument — the scratchpad owns its layout `Arc`, so a wrong-registry misuse is unrepresentable. **Soundness**: effect closures taking `&mut` to the same component type twice are rejected at build time (`assert_distinct_slots` — the slots would alias) — **soft-collected, never a panic**: the recording registry carries an error sink (`RegistryBuilder::push_error`/`take_errors`), and `HtnDomain::build` joins *every* collected error (recording + validation) into one `HtnError::Builder`, so a single build call reports all authoring bugs at once (pinned by `build_reports_every_authoring_error_at_once`); `disjoint_slots` re-checks in debug builds as defense in depth.
- **Selection policies** (`src/selection.rs`): ranking happens once per choice-point visit (precondition validity is constant there); the ranked order is *not* stored in the frame — every policy re-derives it deterministically on revisit (the WeightedRandom sampler's nonce is the restored `plan.len()`), so backtracking resumes down the same ranked list. FirstMatch keeps a fast path (direct `find_method` scan, no ranking). Custom rankers write into a caller scratch Vec; their output is sanitized (omitted valid branches are appended in declaration order — a bad ranker cannot make branches unreachable).
- **Multi-axis utility** (`src/considerations.rs`): `Consideration<A>` — one scoring axis over a planning component with `evaluate` = clamp(0–1) → curve → optional `.invert()` (applied after the curve: `curve(quadratic).invert()` is `1 − x²`) → `.weight()`. `curves::{linear, quadratic, smoothstep, ease_out}` are plain fns. `blend2/3/4` return `impl Fn(&A, …) -> f32` closures — the **weighted average** `Σ wᵢ·vᵢ / Σ wᵢ` (0–1 scale preserved; all-zero weights → 0, never NaN) — which flow straight into the existing `IntoUtility` machinery, so `.utility_fn(blend2(a, b))` needs no new trait impls. Each axis stays individually inspectable (`Consideration::evaluate`).
- **Adversarial planning** (`src/ahtn.rs`, Ontañón & Buro IJCAI 2015 Algorithm 2 + alpha-beta): two players (max/min) decompose from separate root tasks in the SAME baked domain against one shared `PlanState` — register the opponent's root via `DomainBuilder::root(f)` (extra roots must be compounds, validated at bake; forward planning is unaffected). Turns alternate between **executing** the queue head when it is an applicable primitive (depth counts primitive actions issued by either player) and **decomposing** the head compound over its applicable methods (branching = methods, not actions; partial orders schedule the baked first topological order). A player whose next primitive fails its preconditions, whose compound has no applicable method, or that exhausts the shared decomposition budget loses the branch (±∞); max stuck everywhere → `Ok(None)`. Eval is a user closure over the `PlanState`; only max's primitives form the returned plan (the principal variation). The RTS extensions (durative/simultaneous/concurrent actions) are deliberately out of scope — the base algorithm is the turn-based case that fits CDDA.
- **Search strategies** (`src/selection.rs`): `HtnSearchStrategy` on `HtnConfig` (DepthFirst default, DepthFirstFailFast, CostBounded, Custom(Searcher) — MCTS lives in `src/mcts.rs` as a `Searcher` impl: UCT tree policy over decomposition choice points, greedy declaration-order DFS rollouts with backtracking (the paper's shallow-dead-end fix), cost-aware rewards `1/(1+cost)`, dead-end marking (solved-labeling), single-child inlining, incumbent upper-bound pruning; deterministic, no RNG; returns only complete plans or `None`), per-agent `SearchOverride` component overrides strategy/sanity budget. **CostBounded** is branch-and-bound DFS over accumulated primitive cost: the planner tracks `g` (restored per-frame on backtrack like `plan`/`mtr` lengths), records the cheapest *complete* plan at queue-drain and keeps searching (anytime), and prunes commitments/primitive steps whose `g + min_cost(remaining)` cannot strictly beat the best (unannotated primitives cost 0 → degenerates to DepthFirst). `plan_traced` emits `DecompositionTrace` per commitment (Selected/PrecondFailed/Backtracked); the driver bridges to `Messages<DecompositionTrace>` when `HtnConfig.debug_trace` is set. The planner core never touches Bevy event types.
- **ECS execution** (`src/ecs.rs`): `HtnAgent` (component: `Option<Plan>` + cursor + internal `plan_deferral` LOD bookkeeping — the agent's state IS its components), `HtnConfig` (resource: domain + strategy + lookahead/sanity/debug_trace tuning), and `htn_ai_system` (exclusive system, one tick per agent: plan if planless → **re-validate the next step's preconditions against the real world** (drift ⇒ drop plan, replan next tick) → dispatch the action's `EntityCommands` + `world.flush()` (re-extracting the scratchpad afterwards so effects see post-action state) → commit effects to the real components → advance cursor / drop finished plan). Step resolution is a **flat array walk**: `plan.step_task(cursor)` → `domain.tasks[idx]` — no name lookups on the hot path. An empty plan — and a planning `Err` (`NoPlan`/`UnregisteredTask`) — is stored as planless (never wedges the agent). **LOD scheduling** (`PlanEvery(pub u32)` component): an agent carrying it plans **at most once every `n` runs** while planless — execution of an existing plan is never delayed; any planning attempt (success *or* error) resets the deferral to `n - 1`, so unsolvable agents retry at the reduced cadence instead of every tick (pinned by `plan_every_throttles_replanning` — 4 acts in 10 runs at `PlanEvery(3)` vs 10 unthrottled — and `unsolvable_domain_leaves_the_agent_planless_not_wedged`). **Hot-reload** (`hotpatching` feature → `bevy_ecs/hotpatching`, Dioxus Subsecond): `HtnConfig::with_rebuild(domain, rebuild)` stores a domain rebuild closure; the driver change-detects `bevy_ecs::HotPatchChanges` and, on a patch, re-records + re-bakes the domain through it (the baked domain is *data* — compiled closures — so patching task-fn bodies requires a rebuild), swaps it in, drops the parked scratchpad (fresh registry), and clears every agent's plan. A failing rebuild keeps the old domain; the patch tick is recorded either way (no retry loop). Run the game under `dx serve --hotpatch`; only the *tip* crate's task functions are observed.
- **Planner signatures**: `HtnPlanner::plan(&mut self, root_fn, &PlanState) -> HtnResult<Plan>` — symmetric with `BackPlanner`. The root task function is passed **by value** (fn items are zero-sized and their types are unnameable, so turbofish is impossible; the value pins `F` and resolution goes through the baked `TypeId` index — **lookup-by-type, never by name**; names are display-only). Failure is legible, never silent: **`Err(HtnError::NoPlan)`** — the search backtracked past the root with no complete decomposition (a genuine dead end is an error, NEVER an empty `Complete` plan — an empty *success* is a root whose decomposition legitimately has zero steps, and the two are never conflated; `plan_inner` tracks this with an `exhausted` flag set at the four backtrack-past-root exits); **`Err(HtnError::UnregisteredTask)`** — unregistered root fn or out-of-bounds index (the `PlanRoot::Fn` variant carries the fn's `type_name` captured at conversion, so the error names the offending function; the index form formats `<task index N>`); **`Ok` with `PlanStatus::Partial`** — sanity-budget / fail-fast truncation is a value, not an error; `Complete` reports a finished decomposition. `Custom(Arc<dyn Searcher>)` maps a searcher's `None` to `NoPlan`. `set_lookahead`, `set_sanity_limit`, and `set_strategy(HtnSearchStrategy)` — the single strategy knob (DepthFirst default, DepthFirstFailFast, CostBounded, `Custom(Arc<dyn Searcher>)` which bypasses the built-in machinery entirely; it replaces the old independent `set_fail_fast`/`set_cost_bounded` bools whose combination was undefined). Look-ahead is gated by `LookaheadMode` (`set_lookahead_mode`; `set_lookahead(bool)` maps onto it): `Always` (default, full refutation + pins), `Adaptive` — three tiers per commitment: **skip** single-subtask totally-ordered methods with a terminating step (the next queue pop re-checks it against real state), **refutation-only sweep** once a method has been swept `ADAPTIVE_SWEEP_TRIALS` (2) consecutive times without a refutation (per-method streak, reset on refutation, reset per plan — deep-corridor domains sweep one method dozens of times without refuting), **full sweep** otherwise; identical plans to `Always` except a refuted `Complete` can become a truncated `Partial` at a downgraded site under a tight budget — measured on the deep selector domain: Always 145 µs / Adaptive 55 µs / Off 49 µs (the 2× competitor gap analysis: the sweep's compound-survivor analysis re-evaluates every branch of wide selectors, so refutation-only trials + skips recover most of it), `Off` (plain MTR backtracking). The entrypoints are consolidated to `plan` + `plan_traced`, each taking `impl Into<PlanRoot>` — a task function (by value, `TypeId` resolution) or a task index (`usize`: the driver/test-bed form over `domain.root`, and the only way to address GTN-synthesized tasks); an unregistered root is an error, never a panic or a silent empty plan (pinned by `plan_roots_accept_functions_and_indices_alike` and `unregistered_root_yields_an_error`). `BackPlanner::plan(&mut self, goal_fn, &PlanState) -> HtnResult<Plan>` (goal fn by value, same `TypeId` resolution; greedy reverse chaining, compound-aware: candidates are primitives *and* compound methods scored by guaranteed coverage of the needed slots, expanded without backtracking; `HtnError::NoPlan` on plateau, empty MTR, always `Complete`). `Ahtn::search(max_root_fn, min_root_fn, ...)` likewise takes both roots by value. `Plan::mtr() -> &[usize]` (no newtype). `HtnDomain::task_index(task_fn)`/`task_summary(task_fn)`/`goal(goal_fn)` are the typed accessors; `get_task(&str)` remains for display-name introspection only (e.g. walking `plan.names`) — never use it to address planning.
- **Inferred summaries** (`src/summaries.rs`): at bake time every task gets a [`TaskSummary`] — `required_fields` (greatest fixpoint guarded by `term` + `E_f` least fixpoints), `possible_writes`/`guaranteed_writes` (least fixpoints; `.expected` counts as possible, never guaranteed) — plus per-method `possible_writes`. Adapted from Olz/Biundo/Bercher (AAAI 2021 / JAIR 2025); the universe is the **component slot indices** (`ComponentRegistry`), sets are [`FieldSet`] word-bitsets (defined in `src/state.rs` — the universe it indexes is the registry).
- **Look-ahead pruning** (`src/lookahead.rs`, Olz & Bercher SoCS 2023): before committing each method, the sweep runs that **method's own subtask sequence** against an optimistic state (lazily-cloned `PlanState` + an "unknown components" overlay fed by method `possible_writes`; the sequence's last task's effects are never applied). Preconditions on unknown components are "maybe" and never prune. Because effect closures are opaque, every written component conservatively becomes unknown. Verdicts: `DeadEnd` → skip the method; `Refine(pins)` → inevitable refinements pinned per subtask **occurrence** (pins travel on the queue entry). **Budget refutation**: the sweep accumulates `min_yield` and refutes methods that cannot finish within the remaining step budget (subsumes non-terminating tasks, `min_yield == usize::MAX`). Pins never change *which* plan is found — only the effort. **Set semantics** (`set_semantics` flag): for partially-ordered methods the sweep pre-unions every member's `possible_writes` into the overlay and never applies effects sequentially — pruning weakens but stays sound (a dead-end verdict means every member fails in every linearization); pins are keyed by member position, which the first topological order shares.
- **Structure analysis** (in [`TaskSummary`], Toad/Alford-style): `terminating`, `min_yield`, `min_cost`, `recursive`, `self_embedding`, `tail_recursive` — position-tagged reachability over the decomposition graph at bake time. `min_cost` is the min-cost fixpoint twin of `min_yield` (f32, `INFINITY` for non-terminating; primitives contribute their static `.cost`, dynamic `cost_fn` counts 0) and each baked `Method` carries its subtask-sequence `min_cost` sum for CostBounded pruning. Partially-ordered methods use order-independent conservative extensions: `min_yield`/`min_cost`/write sets are sums/unions over members (each runs exactly once); `required_fields` requires a component to be read by a member **no member can write**; structure flags treat every set member as both non-first and non-last.
- **Performance**: task names are interned [`Ustr`]s; the hot loop works on `usize` task indices; [`Plan`] is a **compiled step program** — `steps: Vec<u32>` (domain task indices, execution = flat array walk) plus parallel interned `names` for display. Backtracking is allocation-free: append-only `plan`/`mtr` restored by truncation (frames snapshot `mtr_len` *before* their own method push so a retry replaces the failed entry — a stale MTR entry here is a correctness bug, pinned by `mtr_after_backtrack_records_only_the_chosen_method`), queue suffixes snapshotted per frame as `SmallVec<[_; 4]>` (inline for the common 2–5-subtask case; a persistent/structurally-shared queue making this O(1) is a known future optimization — a bare length is unsound because a completed subtree's frame can be backtracked into after the search consumed part of the suffix, pinned by `backtracking_restores_ancestor_suffix_after_tail_failure`), and the rollback journal (`Rollback`: aligned arena of deep-cloned slot values + `(slot, offset)` ops) restores only the slots each effect wrote — drop-current, clone-back, drop-journal-copy (soundness pinned by `rollback_of_a_replaced_heap_value_frees_everything_exactly_once` / `rollback_of_repeated_unmutated_snapshots_frees_everything_exactly_once`, which use a self-verifying heap cell because drop-counters stay balanced across double-frees). The look-ahead sweep reuses its private `PlanState` clone across sweeps (`copy_from`, no re-allocation), leaves its pin verdicts in the caller's scratch (no `mem::take`), and evaluates each compound method's preconditions once (single pass: survivors collected, then pin + optimistic propagation). The driver reuses one `DriverScratch` resource (agent-entity `Vec` + one `PlanState`, `refresh`ed in place per plan/validate/re-extract phase — zero steady-state allocations; each baked `PrimitiveTask` carries its commit/guaranteed write-slot lists so no per-step collection happens) and plans by root **index** (`plan_index`), not name.
- Error handling goes through `HtnError`/`HtnResult` (`Builder`, `UnknownTask`, `NoPlan`, `SanityLimit`).
- Public API + `prelude` are the seam; keep internals private unless a planner genuinely needs them.

## Work Guidance
- All string-typed identifiers are [`Ustr`]; task/goal names come from `type_name` and are **display/debug metadata only** — planning, goal, and adversarial-root resolution is by the task function's `TypeId` (fn item passed by value; fn-item types are unnameable so turbofish is impossible). Never reintroduce user-supplied name strings or name-keyed planning APIs — the old lookup-by-name surface was removed because `{{closure}}`/`Box<dyn Fn>` names made root/goal resolution fail; a fn-pointer coercion also silently collapses `TypeId`s, so task references must stay fn items.
- New planner algorithm → new module under `src/`, expose through `prelude`, and add tests via the shared `tests/common/mod.rs` `HtnTestBed`. **Domain fixtures live in `benches/common/mod.rs`** (`miner_domain()`, `outpost_domain()`, `gate_domain()`, `doomed_recursion_domain()` — function-defined, the single source of truth shared by tests *and* benches; `tests/common/mod.rs` re-exports them via `#[path]` include). Terminal "done" methods are empty branches (`.branch().precondition(...)` with no `.then`), matching the original fixtures' plan shapes.
- Components participating in planning derive `Component + Clone + Default (+ Debug)`; closure params must be annotated so slot indices can be captured.
- **Generic tasks**: each monomorphization of a generic task fn is a distinct task with its own `TypeId`/summaries (`gather::<Wood>` ≠ `gather::<Stone>`) — the idiomatic way to avoid copy-pasted per-resource branches in large domains, and the seam for data-driven/modded content (a startup pass records the monomorphizations data describes). Pinned by the lib.rs doctest (`task_index` of the two instantiations differs); prefer it over string-keyed task factories, which were removed.
- When wiring into `cdda_sim::ai` later: `cdda_sim` may depend on `bevy_bhtn`, never the reverse.
- **Tests** use the `HtnTestBed` pattern (`tests/common/mod.rs` wraps a built `HtnDomain`, exposes `plan_forward` / `plan_forward_lookahead` / `plan_backward` over `PlanState`s).
- **Benchmarks** live in `benches/ai_throughput.rs` (Criterion, flat miner domain), `benches/deep_ai.rs` (Criterion, deep outpost + Bevy Relationships), `benches/lookahead.rs` (Criterion, look-ahead on/off A/B), and `benches/competitor_comparison.rs` (like-for-like vs `bevy_bae` and a vendored `bevy_htnp` on the shared fetch-item domain). All consume `benches/common/mod.rs` (except the comparison, which is self-contained) and run one **plan → execute-the-full-plan** episode per measured iteration (`execute_plan`; scratchpads reset per iteration — one complete AI decision plus its execution, no replan loop). The first two run the planner **through a real Bevy `Schedule`** via `Query::par_iter_mut` over the multi-threaded executor (scratchpads stored as components; note bevy_ecs 0.18 tuples do NOT imply system ordering — use `.chain()`); their single-actor overhead cases mirror `run_ai`'s exact work shape with `Throughput::Elements(1)` pinned so Criterion's group-wide thrpt column stays sane; `benches/lookahead.rs` calls the planner directly (isolating the algorithmic win from ECS overhead). The comparison bench measures one full episode per actor (end-to-end) plus a **steady-state frame** — one frame of a continuing episode: agents execute/validate their next step, planless agents replan, finished agents reset (amortized) — at 1k/10k/50k agents (deep: 100/1k), single-threaded, each library through its native per-frame cadence; see its module docs for the workload-contract caveats (BAE's per-agent entity trees, htnp's time-sliced planner) and the deep domain's `DEEP_SANITY_LIMIT` requirement.

The deep domain needs `DEEP_SANITY_LIMIT` (1000): the default sanity limit (100 decomposition steps) truncates the ~300-step decomposition to a ~33-step partial plan — pinned by the completion assertions in the episode bench. The deep case has TWO bevy_bhtn encodings: `deep_chain_*` uses a recursive 101-branch FirstMatch selector (`next_step` + recursive root) — the worst-case planning shape, O(n²) branch re-scans (~5,150 evals) that the look-ahead sweep re-walks per commitment (measured: replan 1.2 ms with lookahead, 419 µs without, at progress 0) — and `deep_sequence_*` re-encodes the identical corridor as ONE total-order method (`s0…s99, deep_pickup`), the matched-encoding comparison against BAE's `Sequence` (htnp excluded — its corridor is its own encoding). The matched encoding is ~14× faster to plan (9.4 µs vs 130 µs end-to-end episode) and flips the steady-state frame result: bevy_bhtn 0.23 µs/agent/frame vs BAE 0.84 (frame_100) and 0.11 vs 0.90 (frame_1000) — BAE's old ~2× frame win on `deep_chain_frame` was entirely the selector encoding's amortized replan cost, not execution speed (per-step bhtn execution is cheaper than BAE's flush-per-agent machinery; end-to-end single-actor: 9.4 µs vs 1.48 ms). Trade both linear encodings share: a flattened corridor replans only from its start state (mid-corridor drift recovery is the recursive selector's strength — that encoding stays benchmarked as its own case).

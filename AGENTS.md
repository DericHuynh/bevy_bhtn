# cdda_htn AGENTS.md

## Purpose
Headless **Hierarchical Task Network** planner for CDDA AI. Imports `.htn` files, executes strongly-typed operators via `bevy_reflect`, and runs both **forward** (MTR backtracking over method decomposition) and **backward / goal-state** planning (given a `goal_task`). Combines the classic bevy_htn (forward, DSL, MTR) and bevy_bae (data-driven, composable) shapes into one idiomatic, reflection-driven crate.

## Ownership
- Lives at `crates/cdda_htn/`. The **library (`src/`)** is a leaf: it must **not** depend on ECS (`Component`), `cdda_sim`, `cdda_components`, `cdda_data`, or any world/data crate. Its only Bevy library ties are `bevy_reflect` (reflection) and `bevy_asset` (the optional `.htn` asset loader). Dev-dependencies (tests/benchmarks) **may** pull in `bevy_ecs` to exercise the planner the way a game would — but never a reverse layer dependency.
- Domain data (`HtnDomain`, `Task`, `Method`, `PrimitiveTask`, `HtnCondition`, `Effect`, `Operator`) is plain, reflection-free data — only the **plan state** type needs `Reflect`.
- The library stays headless-testable: planners take `<S: HtnState>` (a `Reflect + Default + Clone + Debug` struct) and never require an `Entity`/`World`.

## Local Contracts
- **API layout**: `parse_htn` (DSL) → `HtnDomain` → `HtnPlanner` (forward) / `BackPlanner` (backward). `Operators` resolve registered `Reflect` types in a `TypeRegistry`. `HtnDomain` precomputes an internal `name -> index` map at parse time so both planners resolve task names in O(1) without rebuilding a map per `plan` call.
- **Inferred summaries** (`src/summaries.rs`): at parse time every task gets a [`TaskSummary`] — `required_fields` (executability-relaxed preconditions, under-approximation), `possible_writes` (over-approximation), `guaranteed_writes` (under-approximation; `expected_effects` count as possible, never guaranteed) — plus a per-method `possible_writes`. Adapted from Olz/Biundo/Bercher's compound-task inference (AAAI 2021 / JAIR 2025) from propositional facts to typed state fields: possible/guaranteed writes are least fixpoints over the decomposition graph; required fields are a **greatest** fixpoint (safety property over all refinements) guarded by least-fixpoint termination (`term`) and f-vanishing (`E_f`) checks, so terminating recursion keeps requirements (every refinement of `Descend → ⟨Descend, Eat⟩ | ⟨Eat⟩` reads `food` first) and non-terminating tasks claim nothing. Fields are interned into `HtnDomain::fields` + a `field -> index` map; sets are [`FieldSet`] word-bitsets.
- **Look-ahead pruning** (`src/lookahead.rs`, Olz & Bercher SoCS 2023): before committing each method choice, the forward planner sweeps that **method's own subtask sequence** against an **optimistic state** (lazily-cloned private state + an "unknown fields" overlay fed by method `possible_writes`; the sequence's *last* task's effects are never applied, so tail-effect methods — the common shape — never clone). Compound tasks contribute unknown fields and are pruned when no method survives; primitives apply effects exactly (literal `Set*` re-knows a field, `Increment*`/`SetIdentifier` inherit trustworthiness). Conditions on unknown fields are "maybe" and never prune — checked **per condition** against precomputed read indices (`prec_reads` on `PrimitiveTask`/`Method`), not per task-union. Verdicts: `DeadEnd` → skip the method at the frame; `Refine(pins)` → inevitable refinements (unique surviving method) pinned per subtask **occurrence** — pins travel on the queue entry `(task, pin)` they were derived for, because recursive domains decompose the same task many times under different states (index-keyed pins are unsound). A pinned occurrence whose method fails skips its proven-infeasible siblings (`DecompositionFrame::pinned`). **Budget refutation**: the sweep also accumulates the sequence's `min_yield` sum and refutes the method when it cannot finish within the planner's remaining step budget — this subsumes non-terminating tasks (`min_yield == usize::MAX` ⟺ `!terminating`), so a task that can only refine forever refutes any method containing it in O(1). The sweep is skipped entirely for hand-built domains without summaries (`summaries.len() != tasks.len()`) and via `HtnPlanner::set_lookahead(false)`; `set_sanity_limit` raises the decomposition-step budget (default 100). Pins never change *which* plan is found — only the search effort; the observable behavioral difference is at the sanity limit (doomed recursion is refuted before it burns the budget, pinned by `lookahead_beats_sanity_limit_on_doomed_method`).
- **Structure analysis** (in [`TaskSummary`], Toad/Alford-style): per task, `terminating` (has a finite refinement), `min_yield` (shortest primitive sequence, `usize::MAX` when non-terminating), `recursive`, `self_embedding` (can appear with material on both sides of itself — Toad's exact-translation boundary), `tail_recursive` (recursion only in last position). Computed at parse time from reachability over the decomposition graph with position-tagged edges (non-last → right-generating, non-first → left-generating).
- **Performance**: all task/method/subtask/field/operator names are **interned [`Ustr`]s** (`Copy`, pointer-identity equality, deref to `str`). The forward planner's hot loop then works entirely on **`usize` task indices** (names are only materialized from the domain's intern pool when the returned `Plan` is constructed); `Plan.tasks` is `Vec<Ustr>`, so copying a plan or comparing task names is constant-time. `get_task` / `task_index` are O(1) via the domain's precomputed `HashMap<Ustr, usize>`.
- **Backtracking is allocation-free**: `plan` and `mtr` are **append-only**, so a [`DecompositionFrame`] stores only the two **lengths** (plus `task` + `skip_next`). On backtrack a `truncate` restores the prefixes — provably identical to cloning the whole `Vec`s, but it removes ~2 heap allocs + O(n) per recursion level. This matters a lot for domains that recursively decompose a root toward the sanity limit (e.g. the miner benchmark), where it cut `plan_one_actor_latency` by ~26% and frame throughput by ~30%.
- **Backtracking restores plan, MTR, and queue**: `plan` and `mtr` are **append-only**, so a [`DecompositionFrame`] stores their two **lengths** (plus `task` + `skip_next`) and a `truncate` restores the prefixes. The task **queue** however is consumed front-to-back, so each frame also snapshots the **queue suffix** at commitment time (`DecompositionFrame::stack`, empty/alloc-free for last-subtask commitments) — restoring it on backtrack is a correctness requirement, not an optimization: without it, siblings behind a failed mid-sequence task are lost (search ends early) or stale ones from the abandoned choice leak into the plan.
- The `bevy_ecs` dev-dependency is built with the `multi_threaded` feature (workspace default) so bench `par_iter_mut` genuinely parallelizes.
- **Backward planning** is deliberately **greedy reverse chaining** (a cheap stand-in for full goal search): it picks the operator that covers the most currently-needed goal fields, applies its effects to a working copy, and repeats. It returns `HtnError::NoPlan` if it plateaus.
- **MTR** is forward-only; backward plans carry an empty MTR.
- Error handling goes through `HtnError` / `HtnResult`.
- Public API + `prelude` are the seam; keep internals private unless a planner genuinely needs them.

## Work Guidance
- All string-typed identifiers in tasks/conditions/effects/operators/`Plan` are [`Ustr`] (see `Cargo.toml`; `ustr` is a normal dependency). Intern at parse time (`Ustr::from`) and everywhere downstream take `Ustr` or `&str` (deref) — never reintroduce `String` for identifiers. `Ustr` is `Copy + PartialEq<&str> + Display`, so existing `&str`-based comparisons still compile unchanged.
- Add/modify grammar in `src/htn.pest` + the pest-parser in `src/dsl.rs` together; keep them 1:1.
- Conditions/effects mutate/read via `bevy_reflect` 0.18 idioms (e.g. `reflect_ref().as_struct()`, `try_downcast_ref`, `reflect_partial_eq`, `reflect_clone`). Do not reintroduce pre-0.18 APIs (`Ref::`, `Reflect::Struct`, `apply_boxed`).
- New planner algorithm → new module under `src/`, expose through `prelude`, and add tests via the shared `tests/common/mod.rs` `HtnTestBed` mirroring `tests/htn_planner.rs`. New/edited `.htn` domains live in the **top-level `htn/` directory** (the single source shared by tests *and* benches) and are pinned in `tests/htn_parse.rs` so the file API stays conformant with the reference `bevy_htn` examples.
- When wiring into `cdda_sim::ai` later: `cdda_sim` may depend on `cdda_htn`, never the reverse.
- **Tests** use the `HtnTestBed` pattern: `tests/common/mod.rs` wraps a parsed `HtnDomain` + `TypeRegistry` and exposes `plan_forward` / `plan_backward`. `tests/htn_planner.rs` pins forward planning (incl. backtracking + idempotent goals), backward planning (reachable + unreachable goals), plan *execution* (applying planned effects to reach the terminal state), and DSL/condition/effect details. - `tests/htn_parse.rs` pins the parser against the reference `bevy_htn` example `.htn` files (in the top-level `htn/`, plus the deep `outpost.htn` derived for benchmarks) so file-API conformance stays stable. `tests/htn_features.rs` pins the **full condition/effect variant matrix** (int/float/`Option`/enum/identifier comparisons incl. negation, all `Set*`/`Increment*` effects), `verify`/`verify_operator` error paths, `expected_effects` chaining, MTR/`Plan::is_preferred_over` ordering, domain helpers (`root_task`/`goal`/`primitive_names`), BackPlanner greedy tie-breaking + multi-leaf composition, `SetIdentifier` verify, and `Parser`/`UnknownTask` error shapes. `tests/htn_summaries.rs` pins the **inferred summaries + look-ahead**: `FieldSet` bit ops, flat-domain summary values (incl. method-level possible writes), terminating recursion (`Loop` guaranteed writes, `Descend` required-survives-recursion), non-terminating recursion (`Spiral` claims nothing as required), `expected_effects` possible-but-not-guaranteed, look-ahead beating the sanity limit on a doomed method, plan-identity when backtracking suffices, unknown-fields-are-"maybe" propagation, queue-restore backtracking incl. tail-failure suffix loss, occurrence-scoped pins, termination-flag dead-ends (pure/nested/mixed + terminating-not-flagged), and per-condition read indices (mixed known/unknown pruning, identifier + notted conditions on unknown fields). `tests/htn_structure.rs` pins the **structure analysis + min-yield budget pruning**: flag/min-yield values across flat, tail-recursive, self-embedding, and non-terminating shapes, budget refutation of a too-deep chain (on vs off), and no over-refutation within budget. `tests/htn_bench_plans.rs` pins the **benchmarks' plans with 100% certainty** (it includes `benches/common/mod.rs` via `#[path]`, so it runs the benches' exact code): exact task sequences for every miner state class and the outpost fresh/marginal/high-fuel states, exact plans for the look-ahead bench domains, plan-identity with the look-ahead off, and the full 10-cycle plan → execute → replan progression (per-cycle plan lengths, head tasks, and final states) for both the miner and outpost loops. `tests/htn_nested.rs` pins **deep nesting** (multi-level compound decomposition order) and **mid-execution replanning** (re-planning against a mutated world state each turn — the stateless-planner equivalent of world state changing while a plan runs). `tests/htn_deep.rs` pins the **deeper `outpost.htn` domain**: depth >= 5, a genuine in-branch backtrack (the "marginal fuel" method is *eligible* but its `Drive` leaf fails), a plan that when executed reaches all objectives, and that high-`fuel` agents take the direct drive branch — so the deep benchmark below measures real, pinned work.
- **Benchmarks** live in `benches/ai_throughput.rs` (Criterion, flat miner domain), `benches/deep_ai.rs` (Criterion, the deep `outpost.htn`), and `benches/lookahead.rs` (Criterion, look-ahead on/off A/B). All three consume the shared `htn/` fixtures through `benches/common/mod.rs` — the single source of truth for domains, state types, initial-state constructors, and the plan-execution helper — which the `tests/htn_bench_plans.rs` certainty tests include directly (`#[path]`) so the tests pin *exactly* what the benches run. Every bench runs a **plan → execute → replan cycle 10 times** per measured iteration (`execute_plan_step`: one action per cycle, the mid-execution replanning loop; states reset per iteration so each iteration does identical work). The first two run the planner **through a real Bevy `Schedule`** (the same path a production app uses, which initializes the `ComputeTaskPool`): 200k miner entities are spawned (each carrying a `MinerState` + reset seed + `Plan` component) and a system plans each entity per frame via `Query::par_iter_mut` over the multi-threaded executor. `benches/deep_ai.rs` additionally makes every colonist carry a real Bevy **Relationship** (`ServesCache` → `CacheMembers`) to a supply-cache entity and seeds plan state from cache resources read through that relationship. `benches/lookahead.rs` instead calls the planner directly (isolating the algorithmic win from ECS overhead) on three domains: `exponential_backtrack` (a doomed 12-gate binary-choice method refuted in one sweep vs 2^12 leaf failures), `doomed_recursion` (sanity-limit burn vs one sweep), and `outpost_deep` (the realistic domain — the honesty check for sweep overhead), each with `set_lookahead` on vs off.

## Verification
- `cargo check -p cdda_htn`
- `cargo test -p cdda_htn` — `tests/htn_parse.rs` (4: reference fixtures + deep `outpost.htn`) + `tests/htn_planner.rs` (9: forward, backward, execution) + `tests/htn_features.rs` (20: condition/effect matrix, verify errors, operators, MTR ordering, expected-effects, Back/execution, domain helpers, error variants) + `tests/htn_nested.rs` (3: deep nesting, mid-execution replanning) + `tests/htn_deep.rs` (5: deep domain semantics, in-branch backtrack, goal reachability) + `tests/htn_summaries.rs` (17: FieldSet ops, summary pins, look-ahead pruning, queue-restore backtracking, termination flags, per-condition reads, occurrence-scoped pins) + `tests/htn_structure.rs` (3: structure flags, min-yield budget pruning) + `tests/htn_bench_plans.rs` (7: exact bench plans, replan-cycle progression) via `tests/common/mod.rs`.
- `cargo bench -p cdda_htn --bench ai_throughput` — flat-miner planner-through-ECS throughput over 10k / 50k / 200k entities and per-actor latency.
- `cargo bench -p cdda_htn --bench deep_ai` — deep (`outpost.htn`) planner-through-ECS throughput + per-actor latency, with every colonist carrying a `ServesCache → CacheMembers` Bevy Relationship read during planning.
- `cargo bench -p cdda_htn --bench lookahead` — look-ahead on/off A/B: exponential-backtrack and doomed-recursion wins, plus the realistic-domain overhead check.
- `cargo check --workspace` and `cargo test --workspace` (full suite) must stay green after adopting the crate.
